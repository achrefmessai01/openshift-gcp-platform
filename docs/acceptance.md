# Technical acceptance book (cahier de recette technique)

| Item        | Value                                           |
|-------------|-------------------------------------------------|
| Solution    | subscriber-api on OpenShift / GCP               |
| Version     | 0.1.0                                           |
| Environments| dev → staging → prod                            |
| Automation  | Robot Framework (`tests/robot`), Bruno (`tests/bruno`), JMeter (`tests/jmeter`) |
| Record      | Generated by `tools/acceptance.py` (`reports/<env>/acceptance-<env>-<date>.md`) |

## 1. Scope and prerequisites

The acceptance validates, for a given environment, that the solution is installed,
reachable, functional, secured and observable as specified in the engineering document.

Prerequisites:

- Cluster reachable, `oc login` works for the pipeline identity.
- Deployment finished (`scripts/deploy.sh <env>` returned 0).
- `API_KEY` of the environment available to the test runner.
- Flows FW-001 (API) and FW-007 (ingress) open from the runner network.

## 2. Test cases

Status column: A = automated (test id in the Robot suites), M = manual.

### 2.1 Smoke (every deployment)

| ID     | Title                                                   | Expected result                                    | A/M |
|--------|---------------------------------------------------------|----------------------------------------------------|-----|
| RT-001 | Liveness endpoint answers 200                            | `GET /healthz` → 200, body `{"status":"ok"}`       | A   |
| RT-002 | Readiness endpoint answers 200                           | `GET /readyz` → 200, body `{"status":"ready"}`     | A   |
| RT-003 | Info endpoint identifies the service and its environment | `service=subscriber-api`, `environment=<env>`, version and hostname present | A |

### 2.2 Functional

| ID     | Title                                                   | Expected result                                    | A/M |

| RT-012 | A created subscriber can be read back                    | 200 with the stored plan                           | A   |

## 3. Acceptance criteria

| Environment | Criteria                                                                                 |
|-------------|------------------------------------------------------------------------------------------|
| dev         | Smoke + functional + security + observability automated tests: 100 % pass                |
| staging     | dev criteria + platform tests + RL-001 gate ACCEPTED + manual RS/RO/RX cases executed once per release |
| prod        | Smoke + platform tests: 100 % pass after deployment; manual cases carried over from staging |

Any failed test blocks the promotion; a waiver needs the L3 lead and the customer
representative signatures with a dated justification.

## 4. How to run

```bash
# Automated suites and record
python tools/acceptance.py --base-url https://<route-host> --env staging --expected-env staging \
  --api-key "$API_KEY" --route-host <route-host> --api-url https://api.<cluster>.<base-domain>:6443

# Performance
jmeter -n -t tests/jmeter/subscriber-api-smoke.jmx -Jprotocol=https -Jhost=<route-host> -Jport=443 \
  -Jthreads=20 -Jduration=120 -JapiKey="$API_KEY" -l reports/staging/jmeter.jtl -e -o reports/staging/jmeter-html
python tools/jmeter_gate.py reports/staging/jmeter.jtl --max-error-rate 1 --max-p95-ms 500

# Exploratory / support
cd tests/bruno && npx --yes @usebruno/cli run --env dev --env-var apiKey="$API_KEY"
```

An example of generated record: [examples/acceptance-record-local.md](examples/acceptance-record-local.md).
